# ADR-004 → ADR-005 → ADR-006 Responsibility Map

| | ADR-004 | ADR-005 | ADR-006 (proposed) |
|---|---|---|---|
| **Title** | The document pipeline targets a document *space* | The Document Intelligence Contract | Evidence Decision & Reconciliation Extension |
| **Owns** | The *scope* promise: broad document coverage + graceful failure, never partial-success-under-a-success-label. The pipeline stage list (acquisition → understanding → entities → accounts → sections → extraction → validation → confidence+evidence → persistence → presentation). The ban on per-institution parsers. | The *representation* every stage above must share: one `PositionedText` shape regardless of native/OCR source. The **entity-level** contract: identity, product/type with confidence+evidence, extraction status (`PRESENT_NO_TRANSACTIONS`/`PRESENT_EXTRACTION_FAILED`/`NOT_DETECTED`), `zeroTransactionsLegitimate` with provenance. Ground-truth matching outcomes (`MATCHED`/`MISSING`/`UNEXPECTED`/`AMBIGUOUS`). The AI boundary. The build sequence (§10). | The *decision* layer above both: **field-level** evidence status for individual scalar values (credit limit, account holder, statement period, transaction date/amount/direction, etc.) — a finer grain than ADR-005's entity contract, and explicitly **not** derivable from structural-source strength alone (§3). **Same-fact correlation** (§4a) — establishing two observations describe the same fact *before* comparing their values. Formal cross-acquisition-source comparison (§4b, native vs. OCR vs. future) for a value both observed, **plus the routing decision** that makes it non-vacuous (§4b — native acquisition is now evidence-gated before OCR is skipped, not skipped merely because native returned something, with the cost tradeoff stated explicitly). **Scope-aware** confirm-time enforcement (§5) that maps each verification finding's existing `suspectedCause` to what it actually implicates, rather than blocking on any `FAILED` finding regardless of scope. **Statement evidence explanation** (§5a) — a required, explainable rendering of the evidence and decision above, not a new decision model. |
| **Does NOT own** | Representation details (that's ADR-005). Field-level or cross-source evidence (that's ADR-006). | Field-level evidence for arbitrary metadata scalars (new in ADR-006). A formal `EvidenceComparison` mechanism between acquisition sources (§8 states the *rule* — disagreement flags, never silently resolved — but not the mechanism). The confirm-time enforcement boundary (ADR-005 governs persistence completeness, not the API-level "may this confirm proceed" gate). | The document-space promise (ADR-004's, unchanged). The entity contract, extraction-status vocabulary, or ground-truth matching outcomes (ADR-005's, unchanged and reused as-is where they already apply). |
| **Terminology this level must not redefine** | — | `PositionedText{confidence, source}`; document-space stage list | `PositionedText`; `PRESENT_NO_TRANSACTIONS`/`PRESENT_EXTRACTION_FAILED`/`NOT_DETECTED`; `MATCHED`/`MISSING`/`UNEXPECTED`/`AMBIGUOUS`; `zeroTransactionsLegitimate`'s `{value, evidence:{source, pages, reason}}` shape; existing verification outcomes `VERIFIED`/`WARNING`/`FAILED`/`NOT_APPLICABLE` (rule-level, unrelated axis — see ADR-006 §2) |
| **Sequencing position** | Written first; scope-setting, no implementation follows directly. | Extends ADR-004. Its own §10 sequence: contract → ground truth → section/entity persistence → native extraction improvements → OCR acquisition → AI interpretation → deterministic validation → corpus regression. | Extends ADR-005's §10, does not reorder it, but is explicit that its own §3 (field-level evidence contract) comes **before** Tesseract production acquisition, not after — OCR is promoted under conservative acquisition semantics (§6) rather than being unconditionally trusted the moment the engine works. The routing-policy change (§4b) ships as its own step, after candidate evidence exists and before cross-source comparison can be non-vacuous. Confirm-time enforcement (§5) and evidence explanation (§5a) still come last. |

**No duplication found**: ADR-006 introduces exactly five concepts absent from ADR-004/005 — field-level evidence status, same-fact correlation, cross-source `EvidenceComparison` (plus the routing decision that makes it reachable in production), scope-aware confirm-time enforcement, and statement evidence explanation — and reuses every existing type/vocabulary rather than renaming or shadowing it. Verified by re-reading both ADRs in full before drafting ADR-006, revised after a first round of review that required source-strength alone to stop being sufficient for `SUPPORTED`, same-fact correlation to precede value comparison, and enforcement to read each verification rule's existing `suspectedCause` rather than block on any `FAILED` finding regardless of scope; revised again in a second round that explicitly approved the routing decision (with its cost tradeoff stated, not left implicit) and added the evidence-explanation requirement.
